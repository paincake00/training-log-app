# DESIGN.md — UI-стандарт приложения «Тренировки»

Обязателен для всех UI-изменений. Продуктовые требования — в `PLAN.md`.

## 1. Принципы

- **Данные важнее декора.** Никаких иллюстраций и лишних панелей там, где нужен лог.
- **Компактно, но читаемо.** Пользователь просматривает тренировки быстро; строки не должны слипаться.
- **Ничего не наползает.** Текст переносится, карточки растут по содержимому, системные панели и клавиатура учитываются.
- **Один акцент.** Спокойная нейтральная база, один зелёный акцент. Прогрессия — визуально важный элемент.
- **Предсказуемость.** Одинаковые элементы выглядят и ведут себя одинаково на всех экранах.
- **Офлайн и тишина.** Никаких сетевых индикаторов, рекламы, баннеров, «премиум» и лишних анимаций.

## 2. Сетка и отступы

Базовая сетка — 4dp.

| Токен | Значение |
|---|---|
| Экранный горизонтальный отступ | 16dp |
| Вертикальный зазор между карточками | 12dp |
| Внутренний padding карточки | 16dp |
| Зазор между заголовком и содержимым карточки | 12dp |
| Зазор между упражнениями в карточке | 12dp |
| Зазор между строкой названия и прогрессией | 4dp |
| Зазор между прогрессией и описанием | 4dp |
| Отступ списка снизу | 24dp + системная навигация |
| Радиус карточки | 16dp |
| Радиус bottom sheet (верх) | 24dp |
| Толщина разделителя | 1dp |

Правила:

- Все списки — `LazyColumn` с `contentPadding`, а не `Column` внутри скролла.
- `Scaffold` + `innerPadding`; edge-to-edge.
- `imePadding()` на экране тренировки.
- Никаких отрицательных отступов и наложений.
- Длинные строки не должны расширять экран: `Modifier.fillMaxWidth()`, `weight(1f)`, `minWidth = 0.dp` где нужно.

## 4. Типографика

Базовый шрифт — системный (Roboto). Прогрессия — `FontFamily.Monospace`.

| Элемент | Стиль | Размер / вес |
|---|---|---|
| Заголовок экрана | `headlineSmall` | 24sp, 600 |
| Заголовок карточки-даты | `titleSmall` | 14sp, 600 |
| День недели в плане | `titleMedium` | 16sp, 600 |
| Название упражнения | `titleMedium` | 16sp, 600 |
| Прогрессия в логе | Monospace, `bodyLarge` | 16sp, 500, lineHeight 22sp |
| Прогрессия в плане | Monospace, `bodyMedium` | 14sp, 500, lineHeight 20sp |
| Прогрессия в редакторе | Monospace, `bodyLarge` | 16sp, 400 |
| Описание в логе | `bodySmall` | 12sp, 400, lineHeight 16sp |
| Описание в тренировке | `bodySmall` | 12sp, 400, lineHeight 16sp |
| Подсказка «По плану» | `bodySmall` | 12sp, 400 |
| Кнопки | `labelLarge` | 14sp, 600 |
| Статус-чип | `labelSmall` | 11sp, 600 |

Правила:

- Прогрессия — всегда моноширинная, чтобы `5/20-5/20` и `60-60-60` не «плясали».
- Не менять регистр и форматирование прогрессии.
- Название: максимум 2 строки в логе (ellipsis), полностью — в тренировке и плане.
- Описание: в логе максимум 2 строки (ellipsis), в тренировке — полностью.
- Заголовки не обрезать без ellipsis.

## 5. Компоненты

### 5.1. WorkoutCard (лог)

```
┌ 25.11.2026 · среда ───────────────────┐
│                                       │
│ Подтягивания                          │
│ 5/20-5/20-5/20-5/0                    │
│ Широкий хват, акцент на негатив       │
│ ─────────────────────────────────────  │
│ Бицепс штанга                         │
│ 8/30-8/30-8/30                        │
│ Стоя, гриф EZ                         │
└───────────────────────────────────────┘
```

- `Surface`, `tonalElevation = 0`, border 1dp `outlineVariant`, radius 16dp.
- Внутренний padding 16dp.
- Заголовок даты + опциональный чип «Черновик».
- Каждое упражнение — `Column`; разделитель между упражнениями.
- Нет фиксированной высоты карточки.
- Тап по всей карточке — открыть тренировку.
- Пустой список упражнений: «Упражнения не добавлены» (`bodyMedium`, `onSurfaceVariant`).

### 5.2. ExerciseLogRow

- `Column`, `fillMaxWidth`.
- Название: `titleMedium`, `maxLines = 2`, ellipsis.
- Прогрессия: Monospace, `primary`, `softWrap = true`. Если пусто — строку не показывать.
- Описание: `bodySmall`, `onSurfaceVariant`, `maxLines = 2`, ellipsis. Если пусто — не показывать.

### 5.3. PlanDayCard

- Карточка дня, аналогичная `WorkoutCard`.
- Заголовок: «Понедельник» / «Сегодня · среда», справа счётчик упражнений.
- Сегодняшний день: border 2dp `primary` или `primaryContainer` фон; без кричащих градиентов.
- Пустой день: строка «Отдых» (`bodyMedium`, `onSurfaceVariant`).
- Упражнение: название + плановая прогрессия + описание (1 строка), меню `⋮` справа. В MVP перестановка — через «Переместить выше/ниже» в меню; drag handle — будущее улучшение.
- Кнопка «+ Добавить» внизу дня.
- CTA сегодняшнего дня: «Начать тренировку» / «Продолжить» / «Открыть».

### 5.4. WorkoutExerciseCard (редактор)

```
┌───────────────────────────────────────┐
│ ≡  Подтягивания              ⋮        │
│    Широкий хват, акцент               │
│    По плану: 8-8-8-8-8                │
│                                       │
│    [ 5/20-5/20-5/20-5/0        ]  ⟳   │
└───────────────────────────────────────┘
```

- Название и описание — по тапу открывают диалог редактирования (глобальные поля).
- «По плану: …» — `bodySmall`, `onSurfaceVariant`; показывать, если плановая прогрессия непустая.
- Поле прогрессии — `OutlinedTextField`/`BasicTextField`:
  - моноширинный;
  - `minLines = 1`, `maxLines = 6`;
  - без автоформатирования;
  - `KeyboardType.Text` (нужны `-`, `/`, цифры);
  - занимает всю доступную ширину.
- Иконка reload — 48dp touch target, `contentDescription = "Обновить прогрессию в плане"`; только для `IN_PROGRESS`.
- Drag handle — 48dp, слева.
- Меню `⋮`: «Изменить название и описание», «Удалить упражнение».
- Карточка растёт по содержимому.

### 5.5. ExercisePickerSheet

- `ModalBottomSheet`, максимум 85% высоты.
- Заголовок «Добавить упражнение».
- Поиск: `OutlinedTextField` с иконкой, placeholder «Поиск упражнения».
- Список:
  - название — `titleMedium`, 1 строка;
  - описание — `bodySmall`, 1 строка, ellipsis;
  - последняя прогрессия — Monospace, `bodySmall`, `primary`, 1 строка.
- Высота строки — не фиксированная, минимум 64dp.
- Кнопка «Создать новое упражнение» — `OutlinedButton` внизу, вне скролла.
- Пустой поиск: «Ничего не найдено».

### 5.6. Диалоги упражнения

- Создание: название (обязательно), описание, прогрессия.
- Редактирование: название, описание; предупреждение:
  «Название и описание общие для всех тренировок. Изменения применятся везде.»
- Ошибка пустого названия — `supportingText` красным, кнопка сохранения неактивна.
- Кнопки: «Отмена» (text), «Сохранить»/«Добавить» (filled).
- Поля не должны уходить под клавиатуру; диалог скроллится при необходимости.

### 5.7. Статус-чип

- «Черновик»: `secondaryContainer` / `onSecondaryContainer`, radius 8dp, padding 6×2dp.
- «Завершена»: не показывать яркий чип; достаточно галочки/приглушённого текста в заголовке.
- Не использовать чипы для декора.

### 5.8. EmptyState

- Иконка 48dp, `onSurfaceVariant`.
- Заголовок `titleMedium`.
- Пояснение `bodyMedium`, `onSurfaceVariant`, максимум 2 строки.
- Опциональная CTA.
- Вертикальные отступы 32dp, по центру.

### 5.9. Snackbar

- Показывать только значимые подтверждения:
  - «Прогрессия обновлена в плане и пресете»;
  - «Обновлена только последняя прогрессия»;
  - «Упражнение уже добавлено»;
  - «Тренировка завершена»;
  - ошибки сохранения.
- Не показывать snackbar на каждое автосохранение.

## 6. Экраны

### 6.1. Лог

- Top app bar: «Тренировки».
- CTA на сегодня:
  - «Начать тренировку» — filled, full width или extended FAB;
  - «Продолжить тренировку» — filled tonal;
  - «Открыть тренировку» — outlined.
- CTA не должна перекрывать карточки: добавляй нижний padding списку.
- Список карточек, новые сверху.
- Пустое состояние: «Пока нет тренировок» + «Начать тренировку».

### 6.2. План

- Top app bar: «Недельный план».
- Список 7 карточек.
- Порядок фиксированный: понедельник → воскресенье.
- Сегодняшний день выделен.
- В каждом дне — меню `⋮` с перестановкой «выше/ниже», добавление. Drag handle — будущее улучшение.
- Никаких вкладок по дням: пользователь должен видеть весь план скроллом.

### 6.3. Тренировка

- Top app bar: дата, статус, меню.
- Список карточек упражнений.
- Кнопка «Добавить упражнение» внизу списка.
- Bottom bar: «Завершить тренировку» (для `IN_PROGRESS`) или «Тренировка завершена» (для `COMPLETED`).
- `imePadding()` обязателен.
- При фокусе на поле прогрессии оно должно быть видно над клавиатурой.
- Пустое состояние, если упражнений нет.

## 7. Взаимодействие и движение

- Стандартные переходы Material 3; длительность 150–250 мс.
- Drag-and-drop: подъём строки, лёгкая тень/масштаб, haptic feedback на старте.
- Если drag-библиотека недоступна — кнопки «вверх/вниз» в меню; функция обязательна.
- Удаление — только через меню + `AlertDialog`; без swipe-to-delete.
- Завершение тренировки обратимо через «Вернуть в работу».
- Автосохранение тихое; индикатор «Сохранено» не нужен.
- Ошибки — snackbar или inline в диалоге.

---

## 8. Доступность

- Минимальный touch target — 48×48dp.
- Все иконки-действия — с `contentDescription`.
- Контраст текста — не ниже 4.5:1.
- Поддержка системного масштаба шрифта минимум до 1.3× без обрезки и наложений.
- Фокус-порядок логичный: заголовок → поля → действия.
- Не полагаться только на цвет: статус дублировать текстом/иконкой.
- Диалоги и bottom sheet закрываются кнопкой «Назад».

---

## 9. Тексты

- Русский, коротко, без восклицаний и технического жаргона.
- Все строки — в `strings.xml`.
- Примеры:
  - «Начать тренировку»
  - «Продолжить тренировку»
  - «Открыть тренировку»
  - «Завершить тренировку»
  - «Тренировка завершена»
  - «Вернуть в работу»
  - «Добавить упражнение»
  - «Создать новое упражнение»
  - «По плану: …»
  - «Отдых»
  - «Черновик»
  - «Упражнение уже добавлено»
  - «Название и описание общие для всех тренировок. Изменения применятся везде.»
  - «Прогрессия обновлена в плане и пресете»
  - «В плане на этот день упражнения нет. Обновлена только последняя прогрессия»
- Даты: `25.11.2026 · среда`.
- Не использовать «Вы»; обращение безличное или «ты» не требуется.

## 10. Запрещено

- Хардкод строк в Compose.
- Фиксированные высоты текстовых контейнеров.
- Горизонтальный скролл основного контента.
- Обрезка текста без ellipsis.
- Несколько конкурирующих акцентов.
- Свайп-удаление.
- Скрытие описания в тренировке.
- Автоформатирование прогрессии.
- Сетевые индикаторы и любые сетевые элементы.
- Анимации дольше 250 мс и декоративные эффекты.

---

## 11. Чек-лист UI перед сдачей

- [ ] Светлая и тёмная тема выглядят корректно.
- [ ] Длинное название (2+ строки) не ломает карточку.
- [ ] Длинное описание в логе обрезается с ellipsis, в тренировке видно полностью.
- [ ] Длинная прогрессия переносится и не уезжает за экран.
- [ ] Системный шрифт 1.3× не приводит к наложениям.
- [ ] Клавиатура не закрывает активное поле.
- [ ] Status bar / navigation bar не перекрывают контент.
- [ ] Все кнопки ≥48dp и имеют `contentDescription`, где нужно.
- [ ] Пустые состояния есть на всех экранах.
- [ ] Snackbar не спамит.
- [ ] Нет хардкод-строк.
